# analysis/

Dated notes, extracted training curves, and the figures built from them.

## What goes here, and what does not

The git log already records **what was done**. These notes record **what was learned** —
the measurement, the number, and what it ruled out. If a session produced no new fact,
it should produce no note; a log padded with "did X" entries stops being read, and an
unread log is worse than none.

A note is worth writing when one of these is true:

- a hypothesis was **killed by a measurement** (write the measurement, not the conclusion);
- a number will be **cited later** — throughput, a loss, an error budget;
- a decision was made whose **reasoning is not in the code** and would look arbitrary to
  someone reading the diff a month later.

## Convention

```
analysis/YYYY-MM-DD_<topic>.md
```

Start with the conclusion. Put the evidence under it, with enough detail to re-run.
State explicitly what the measurement **cannot** show — most of the wrong turns in this
project came from a result that was true but narrower than it was read to be.

`analysis/2026-08-04_job233052_report.md` is the worked example: it opens with the
experimental design and its own limitation (five variables changed at once, so nothing is
attributable), then the measurements, then the hypotheses each one eliminated.

## End of a work session

Two things, in order of importance:

1. **Update the "Current status" block in `CLAUDE.md`.** Ten lines: what works, what is in
   progress, what is blocked, what is next. This is what the next session reads first, and
   it is cheap enough that there is no excuse for it being stale.
2. **Add a dated note only if something was learned.** See above.

Both are for the reader who has no context — which within a week includes you.

## Files

| | |
|---|---|
| `*_report.md` | dated notes |
| `run_*_curves.csv`, `run_*_per_var.csv` | training curves extracted by `tools/events_to_csv.py` |
| `training_analysis.ipynb` | the figures, re-runnable |
| `figures/` | exported PNGs, regenerated by `export_figures.py` |

Raw TensorBoard event files and `.nc` copies are gitignored: they run to tens or hundreds
of megabytes and the CSV extract is what the figures actually read.
