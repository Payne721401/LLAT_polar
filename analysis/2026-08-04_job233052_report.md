## 3. 成因分析

### 3.1 已排除

| 假說 | 檢驗 | 結論 |
|---|---|---|
| 過擬合 | train vs val 同步、val 較低 | ❌ 排除 |
| **Vt/Vr 標準化離群值** | 抽 600 檔測標準化後最大值:vt 8.7σ / vr 8.9σ / vt10 6.9σ / vr10 7.3σ | ❌ **排除**(全 < 10σ,統計檔的 1,000 檔抽樣足夠) |
| warmup 不足 | warmup 於 step 1,000 結束;首次 spike 在 step ~5,400 | ❌ 排除(時序不符) |

### 3.2 主要證據:LR 與穩定性的關係

把 231 個驗證點的 val_loss 對「當時 LR」作圖:

```
76 次 spike  ——  全部發生在 LR > 6.06e-05
LR < 6.06e-05 之後  ——  一次 spike 都沒有
```

**經驗穩定閾值 ≈ 6e-5。**

### 3.3 未解的核心疑問

> **baseline 用同樣的峰值 LR(4e-4)卻全程穩定,為何本次不穩定?**

而且理論上**更大的批次應該更穩定**(等效批次 4 → 32,梯度雜訊降低),
本次的不穩定與此預期相反。剩餘的候選差異:

| 候選 | 評估 |
|---|---|
| **精度 bf16 vs fp32** | 最可能。bf16 尾數僅 8 bits(fp32 為 24)。但原版 LLAT 用 fp16 訓練成功,故低精度本身非充分條件 |
| **變數 vt/vr** | 次可能。`r = linspace(0, r_max, R)` **包含 r=0**,該處所有 θ 對應同一物理點,但 vt/vr 隨 θ 正弦變化 ⇒ 中心環存在物理上無意義的高頻樣式 |
| 網格 R=41 | 較不可能,但改變了 loss 的平均對象 |

**判別方法(資料已存在)**:event 檔中已記錄 `gradient_2norm`。
- 梯度範數與 loss **同步暴衝** ⇒ 梯度爆炸(LR / 精度)
- 梯度範數**平穩**而 loss 暴衝 ⇒ 前向傳播或資料問題

匯出工具已更新以包含此欄位,下一步優先檢視。


### 3.4 梯度範數分析(✅ 決定性證據,2026-08-04 補充)

`train.py` 已記錄 `gradient_2norm` 與逐層 `grad_2.0_norm/*`,兩次訓練對照:

| | 中位數 | 最大 | 超過 clip=2.0 |
|---|---|---|---|
| **baseline**(u/v, fp32, batch 4) | **0.28** | 194 | **0.8%** |
| **本次**(vt/vr, bf16, batch 32) | **3.8 × 10⁶** | 4.4 × 10¹³ | **95.6%** |

**中位數相差 1,300 萬倍。**

#### (a) 排除輸入標準化

共用的統計檔中有三個變數標準差極小:`q` 1.72e-07(放大 5.8×10⁶)、
`f` 3.07e-05、`tp` 8.22e-04。但**兩次訓練用的是同一份檔案**,baseline 梯度仍維持 0.28,
**故排除**。新算的 vt/vr 統計亦正常(各層 std 4–12)。

#### (b) 時序:梯度是「逐步惡化」,非一開始就壞

```
step 0        gradient_2norm 0.96      正常
step 2,269    val_loss 最佳 0.30065
step 3,508    gradient_2norm 0.135     全程最小(最健康)
step ~5,400   首次 spike,梯度開始失控
step 105,000  gradient_2norm 7.4×10⁵   完全失控
```

若為輸入標準化問題,第一步就會爆 —— **時序再次排除該假說**。

#### (c) 逐層分布:爆炸集中在輸入端

| 層 | 梯度中位數 |
|---|---|
| `layer1.blocks.0.attention.qkv.weight` | **2.17e6** |
| `patch_embed.conv_upper.weight` | **2.16e6** |
| `layer1.blocks.1.attention.qkv.weight` | 5.16e5 |
| `patch_embed.conv_surface.weight` | 5.48e4 |
| `layer2.blocks.0.attention.qkv.weight` | 4.91e4 |
| ⋯ | |
| `layer3.blocks.*.attention.proj.bias` | **~1e-6** |

**跨層相差 12 個數量級。** 架構為
`patch_embed → layer1 → downsample → layer2 → layer3 → upsample → layer4(+skip from layer1) → patch_recover`;
layer1 經 **U-Net skip connection** 直達 layer4,繞過深層路徑。梯度在此捷徑上放大,
深層(layer3)幾乎無梯度 ⇒ **網路實質退化為僅用淺層捷徑學習**。

#### (d) 裁剪已飽和,失去保護作用

95.6% 的步驟被壓到 norm = 2.0 ⇒ 優化器實際在做**固定步長**更新,
實際步長 = `lr × clip_val`。梯度再大也不改變步長,但**更新方向已惡化**。

#### (e) 推定機制(❓ 仍需實驗確認)

```
LR 過大 → 壞更新 → 激活值放大 → 梯度放大 → 裁剪飽和
       → 步長固定但方向持續惡化 → 正回饋失控
```

**但仍未解:baseline 用同樣的峰值 LR(4e-4)為何不會如此?**
剩餘變因:**bf16 精度**、**R=41 網格**、**vt/vr 表示法**。

#### (f) 關於 vt/vr 的補充事實

- 資料集**已預先存好** `vt`/`vr`/`vt10`/`vr10`,**本專案未執行任何旋轉**,
  僅讀取後以 `latlon_to_polar` 從笛卡兒 81×81 內插至 (r,θ)。
  ⇒ **其定義與慣例未經本專案驗證**。
- 訓練端 `r = linspace(0, r_max, R)` **包含 r=0**。該處 vt/vr 方向未定義(奇點),
  180 個 θ 全部取到同一格點值,但物理上 vt 應隨 θ 正弦變化 ⇒ 目標自相矛盾。
  惟該環僅佔 1/41 格點,**是否足以造成 1e6 量級梯度,尚無證據**。

### 3.5 補充證據(2026-08-04 下午,直接解析 event 檔)

#### (a) 排除「單一變數壞掉」—— 98 個變數的尖峰在時間上同步

逐變數訓練損失 `train_norm_L1/*` 的最大值發生時刻高度集中:

| 發生 step | 有幾個變數在此達到最大 |
|---|---|
| 38,105 | 26 個(27%) |
| 41,991 | 19 個(19%) |
| 42,310 | 16 個(16%) |

而且**所有變數的天花板都是 20–23σ**,與變數種類無關。

> ⚠️ 若只看「放大倍數」排名會誤判:`lat` 555×、`f` 542×、`doy_cos` 534× 看似特別壞,
> 但那是**分母假象**——這些變數本來就好預測(早期損失 0.037),分子則和大家一樣是 ~21。
> **結論:是模型輸出整體崩潰,不是某個變數的資料有問題。**

#### (b) 統計檔逐變數比對 —— 完全清白

把新算的 `stat_std_vtvr.nc` 與原版 `stat_std.nc` 的 **31 個共用變數逐一相除**:

```
ratio 全部 = 1.0(rtol 1e-6)     只在新版:vt, vr, vt10, vr10
```

即新統計檔是原版的**乾淨超集**,未動到任何既有變數。
`q` 的 std = 1.72e-07 出現在 **50 hPa**(平流層極乾),逐層檢視合理:

```
 50 hPa 1.7e-07 → 500 hPa 1.6e-03 → 1000 hPa 4.2e-03
```

**§3.4(a) 的推論由此獲得直接驗證,不再只是「baseline 共用同檔」的間接論證。**

#### (c) 關鍵:梯度爆炸與損失尖峰是**兩件獨立的事**

| step | train_loss | gradient_2norm |
|---|---|---|
| 38,105 | **6.46** | 1.40e6 |
| 38,221 | 0.61 | 2.11e6 |
| 38,279 | 0.45 | 1.00e6 |
| 38,308 | **0.41**(正常) | **3.97e6**(照樣爆) |

且損失尖峰**只出現在 step 22,793 – 42,542** 這個有界區間(全程 3,620 個紀錄點中僅 27 個 > 5,佔 0.75%),
之後完全停止;但**梯度範數從頭到尾都是 1e6 量級**。

> **這改寫了 §3.4(e) 的推定機制。**
> 「LR 過大 → 踩到損失懸崖」只能解釋**尖峰為何隨退火消失**,
> 不能解釋**損失健康時梯度仍是 1e6**。
> 損失曲面本身沒有懸崖 —— 問題在**反向傳播的梯度尺度整體偏大**,
> 這與 §3.4(c) 的「跨層相差 12 個數量級」是同一件事的兩個面向。
>
> ⇒ 最可疑的剩餘變因由「LR」轉為 **bf16 精度**(baseline 為 fp32),
> 診斷 A 的優先序因此高於診斷 B。

1. 讓它在 NCHC H200 上**跑得完**
2. 找出「值都怪怪的」的**成因**
3. 建立**可重現、可對照**的實驗流程(而不是一次改五件事)

---

### 第二幕:診斷與工程(S4–S8)

**S4 — 先做的事:把架構的疑慮測掉**(時間不夠可刪)
- 曾懷疑三件事:θ 週期性、接縫、旋轉等變性。
- **實測結論:對這個 transformer 全都不是問題。** 因為它用**非重疊 patch embed**
  (stride = patch)+ 視窗注意力,θ 只要整除就完全不填充、也沒有跨邊界的重疊卷積
  ⇒ **沒有接縫成因**。循環填充 vs 零填充、拆 mask vs 留 mask,接縫比值全都 ~1.0。
- 這是**姊妹作 DSAT-2D(CNN)才有的問題**,不能直接套過來。
- 一句話:**「花時間證明某件事不是問題,和解決問題一樣有價值。」**

**S5 — 核心診斷:baseline 從未退火**
- 這是全場最強的一張。
- `max_steps` 設 1,600,000,實際只跑到 252,000(**15.8%**)
  ⇒ cosine 只走了開頭 ⇒ 訓練結束時 **LR 仍在峰值的 94%**。
- **模型從來沒有進入精修階段就被時間砍斷。**
- 配圖:兩條 LR 曲線疊圖(baseline 幾乎水平 vs 本次完整下降到 4e-11)。

**S6 — 工程:80× 吞吐**
- 每 epoch **2.85 小時 → 2.1 分鐘**;牆鐘 199.6 h → **6.7 h**。
- **關鍵是可分解驗證,不是喊數字**:
  `8 GPU (8×) × bf16 (2×) × 網格 R=41 (4.3×) × 移除死路徑 (1.18×) ≈ 81×`,實測 80×。
- DDP 正確性佐證:steps/epoch = 454 = 14,528/(4×8);baseline 是 3,706 ⇒ **等效只用了 1 張卡**。

**S7 — 順手修掉的問題**
- 挑三個講就好,重點在「**怎麼驗證修對了**」:
  1. `earth_specific_bias` 死路徑:全零、非 Parameter、每步 CPU→GPU 搬 26 MB
     → 移除後**輸出逐元素相同(max diff 0.000e+00)**、forward 快 18%。
  2. 驗證用 `batch_size` 寫死 1 → 改 4,驗證時間佔比 20% → 3%。
  3. θ 跨縫 attention mask:週期軸上禁止跨縫在語意上是錯的 → 拆除。
- 一句話:**「bit-identical 是重構的驗收標準。」**

**S8 — 假說驗證成功**
- LR 退火完成度 **6% → 100%**,排程完整執行。
- **對 baseline 的診斷得到證實。**

---

### 第三幕:誠實的新問題(S9–S12)

**S9 — 但是:模型在第 5 個 epoch 就達到最佳**(誠實的轉折)
- 最佳 val_loss 0.30065 @ epoch 5;最終 0.33168 @ epoch 231。
- **後續 226 個 epoch、98% 的算力是負貢獻。**
- 先排除最直覺的解釋:**不是過擬合**——train 與 val 同步震盪,且最終 val (0.3317)
  **低於** train (0.3364);過擬合的特徵是 train 續降、val 上升,與觀察相反。

**S10 — 找到決定性證據:梯度爆炸**
- 一張表講完:

  | | 梯度範數中位數 | 超過 clip=2.0 |
  |---|---|---|
  | baseline | **0.28** | 0.8% |
  | 本次 | **3.8 × 10⁶** | **95.6%** |

- **相差 1,300 萬倍。** 95.6% 的步驟被裁剪 ⇒ 優化器實際在做**固定步長**更新,
  **有效學習率由裁剪決定,而非由排程決定**。
- 逐層分布:爆炸集中在**輸入端**(`patch_embed` 2.16e6、`layer1.qkv` 2.17e6),
  深層 `layer3` 僅 ~1e-6,**跨層相差 12 個數量級**
  ⇒ 網路實質退化為只用 U-Net skip 的淺層捷徑學習。

**S11 — 排除法:四個假說死了三個**
- 這張展示的是**方法**,不是結論:

  | 假說 | 如何否證 |
  |---|---|
  | 過擬合 | train/val 同步且 val 較低 |
  | 輸入標準化異常 | 與原統計檔逐變數比對,31 個共用變數 ratio 全 = 1.0 |
  | 某個變數的資料壞掉 | 98 個變數的損失尖峰**在時間上同步**、天花板一致 ⇒ 全域事件 |
  | warmup 不足 | warmup 於 step 1,000 結束,首次 spike 在 step ~5,400(時序不符) |

- 最新發現讓假設進一步收斂:**損失健康(0.41)時梯度照樣 4e6**
  ⇒ 不是「LR 踩到損失懸崖」,是**梯度尺度本身的問題** ⇒ 主嫌從 LR 轉為 **bf16 精度**。

**S12 — 方法論的自我批評**(這張會加分)
- 本次一口氣改了**五項**(變數 u/v→vt/vr、網格 R=201→41、精度 fp32→bf16、
  批次 4→32、`max_steps`)⇒ **成因無法歸因**。
- 已建立的補救:`OVERLAY` / `RUNDIR` / `FRESH` 三個環境變數,
  讓每個實驗只記錄差異、各自獨立、可安全並行。
- 一句話:**「這是我這次最大的方法論錯誤,也是我為此建的工具。」**

### 收尾(S13–S14)

**S13 — 下一步(單變數對照)**
- 診斷 A:`bf16 → fp32`(其餘不動)
- 診斷 B:`LR 4e-4 → 5e-5`(其餘不動)
- 判讀準則明確:**哪一個能讓 `gradient_2norm` 回到 O(1),即為主因。**
- 只需 30 epochs(~13,600 步,< 1 小時)—— 因為原始訓練在 step ~5,400 就開始失控。
- 兩者皆無效 ⇒ 指向 R=41 網格或 vt/vr 表示法。

**S14 — 推論端的待修清單**(見 §7)
- 誠實說明:**目前無法產出極座標版的預報圖**,原因是推論鏈有 4 個 blocker。
- 但其中一個是**科學收穫**:`polar_to_latlon` 的 `fill_value=0` 讓四角 **21.5%** 的格點歸零,
  這正是學姊圖上「最外圈壞值」的直接成因 —— **老問題找到答案了**。

### 給問答準備的三題

1. **「為什麼 val_loss 不能直接和 baseline 比?」**
   → loss 是對**標準化後**的變數取平均。變數表換了(標準差不同)、網格換了(平均的格點數不同),
   尺度與平均對象都不同。**可比的是退火完成度、穩定性、吞吐**這三項。

2. **「80× 是不是因為換了小網格才快?」**
   → 網格只佔 4.3×,GPU 數佔 8×、精度佔 2×。**且可分解驗證與實測吻合(81 vs 80)。**

3. **「極座標到底有沒有比較好?」**
   → **目前還不知道,而且我不會假裝知道。** 本次的價值在**診斷與工程**,
   精度比較必須等單變數診斷完成、訓練穩定之後才能做。

## 7. 推論端待修清單(2026-08-04 盤點)

推論鏈**目前無法產出極座標預報圖**。以下依「是否擋住執行」分級。
主檔案:`DLAMPty_inference.py`(polar 版)、`export_onnx.py`、`onnx/LLAT_polar_v1.yaml`。

### 7.1 Blocker(不改就跑不動)

| # | 位置 | 問題 |
|---|---|---|
| **I1** | `export_onnx.py:24` | `input_sample` 仍是 `(1,13,81,81,6)` / `(1,81,81,20)` 的**笛卡兒形狀**,極座標應為 `(1,13,41,180,6)` / `(1,41,180,20)` |
| **I2** | `onnx/LLAT_polar_v1.yaml` | 變數表寫 `u, v, u10, v10`,訓練用的是 **`vt, vr, vt10, vr10`**;統計檔指向 `stat_mean.nc` 而非 **`stat_mean_vtvr.nc`** |
| **I3** | `DLAMPty_inference.py:300-301, 319-320` | 硬編碼 `R=201`,訓練模型是 **R=41** ⇒ ONNX shape mismatch |
| **I4** | `onnx/` | **沒有 `.onnx` 權重**,只有 yaml。需先從 `vl0.3006494` checkpoint 匯出 |

### 7.2 正確性(能跑但結果錯)

| # | 位置 | 問題 |
|---|---|---|
| **I5** | `polar_to_latlon(fill_value=0.0)` | `r_max=40` 格 = **10°**,但 81×81 的角落距中心 **14.1°** ⇒ **21.5% 的格點被填 0**。**這是學姊圖上「最外圈壞值」的直接成因** |
| **I6** | `DLAMPty_inference.py:324-331` | `lonlat_uniformizer` 從**已被歸零的** lon/lat 場估中心 ⇒ 中心估計被 21.5% 的 0 值拉偏。可能是 +24h 中心差 350 km 的來源 |
| **I7** | `DLAMPty_inference.py:331` | `np.meshgrid(...)` 寫在 `if self.uniformize_lonlat:` **區塊外**;該旗標為 False 時 `lon`/`lat` 未定義 ⇒ `NameError`。目前預設 True 才沒炸 |
| **I8** | `latlon_to_polar:43` | `r = linspace(0, r_max, R)` **含 r=0**,180 個 θ 取到同一點。對 vt/vr 尤其矛盾(vt 應隨 θ 正弦變化) |
| **I9** | `IC_from_xarray_to_npy` | 推論輸入是 ERA5 的 **u/v**,模型要 **vt/vr**,中間**沒有轉換** |

> ⚠️ **I8 不能只改推論端。** 訓練時 r 從 0 起算,推論端若改成 `r_min = Δr/2`,
> 兩邊網格定義不一致,結果會系統性偏移。**這一項必須與下次訓練一起改。**

### 7.3 耦合(two-way)

| # | 問題 |
|---|---|
| **I10** | `inference_2_way_test_polar.py` 走 `interaction_tools/`,該處硬編碼 81×81。`polar_to_latlon` 輸出剛好是 81×81,形狀對得上;但**邊界置換的外圈 8 格在角落處會拿到 I5 的 0 值**。7.5° 回饋半徑 < 10° 故主回饋區安全 |

### 7.4 建議修復順序

```
I2 (改 yaml,5 分鐘)
  → I1 (改 export 形狀)
  → I4 (匯出 onnx)          ← 到這裡才有東西可跑
  → I3 (R/Θ/r_max 改為從 yaml 讀,不再硬編碼)
  → I5+I6 (改 fill_value=NaN + 遮罩,或把 r_max 放大到 √2×40 涵蓋角落)
  → I9 (u/v → vt/vr 轉換)
  → I7 (縮排修正,順手)
  → I8 (延後,與下次訓練同步改)
```

**I5 的兩個修法要先決定**:
- **(a) 保守**:`fill_value=np.nan` + 下游遮罩 ⇒ 角落誠實標記為「模型未涵蓋」,畫圖留白。
- **(b) 積極**:訓練時就把 `r_max` 放大到 `40√2 ≈ 56.6` 格 ⇒ 極座標盤涵蓋整個方形域,無角落缺口。
  代價是格點數增加,且外圈取樣密度更稀疏。
- **建議先做 (a)**,因為 (b) 要重新訓練,而 (a) 立刻能讓圖變乾淨、也誠實。
