## 3. 成因分析

### 3.1 已排除

| 假說 | 檢驗 | 結論 |
|---|---|---|
| 過擬合 | train vs val 同步、val 較低 | ❌ 排除 |
| **Vt/Vr 標準化離群值** | 抽 600 檔測標準化後最大值:vt 8.7σ / vr 8.9σ / vt10 6.9σ / vr10 7.3σ | ❌ **排除**(全 < 10σ,統計檔的 1,000 檔抽樣足夠) |
| warmup 不足 | warmup 於 step 1,000 結束;首次 spike 在 step ~5,400 | ❌ 排除(時序不符) |

### 3.2 主要證據:LR 與穩定性的關係

把 231 個驗證點的 val_loss 對「當時 LR」作圖:

```
76 次 spike  ——  全部發生在 LR > 6.06e-05
LR < 6.06e-05 之後  ——  一次 spike 都沒有
```

**經驗穩定閾值 ≈ 6e-5。**

### 3.3 未解的核心疑問

> **baseline 用同樣的峰值 LR(4e-4)卻全程穩定,為何本次不穩定?**

而且理論上**更大的批次應該更穩定**(等效批次 4 → 32,梯度雜訊降低),
本次的不穩定與此預期相反。剩餘的候選差異:

| 候選 | 評估 |
|---|---|
| **精度 bf16 vs fp32** | 最可能。bf16 尾數僅 8 bits(fp32 為 24)。但原版 LLAT 用 fp16 訓練成功,故低精度本身非充分條件 |
| **變數 vt/vr** | 次可能。`r = linspace(0, r_max, R)` **包含 r=0**,該處所有 θ 對應同一物理點,但 vt/vr 隨 θ 正弦變化 ⇒ 中心環存在物理上無意義的高頻樣式 |
| 網格 R=41 | 較不可能,但改變了 loss 的平均對象 |

**判別方法(資料已存在)**:event 檔中已記錄 `gradient_2norm`。
- 梯度範數與 loss **同步暴衝** ⇒ 梯度爆炸(LR / 精度)
- 梯度範數**平穩**而 loss 暴衝 ⇒ 前向傳播或資料問題

匯出工具已更新以包含此欄位,下一步優先檢視。


### 3.4 梯度範數分析(✅ 決定性證據,2026-08-04 補充)

`train.py` 已記錄 `gradient_2norm` 與逐層 `grad_2.0_norm/*`,兩次訓練對照:

| | 中位數 | 最大 | 超過 clip=2.0 |
|---|---|---|---|
| **baseline**(u/v, fp32, batch 4) | **0.28** | 194 | **0.8%** |
| **本次**(vt/vr, bf16, batch 32) | **3.8 × 10⁶** | 4.4 × 10¹³ | **95.6%** |

**中位數相差 1,300 萬倍。**

#### (a) 排除輸入標準化

共用的統計檔中有三個變數標準差極小:`q` 1.72e-07(放大 5.8×10⁶)、
`f` 3.07e-05、`tp` 8.22e-04。但**兩次訓練用的是同一份檔案**,baseline 梯度仍維持 0.28,
**故排除**。新算的 vt/vr 統計亦正常(各層 std 4–12)。

#### (b) 時序:梯度是「逐步惡化」,非一開始就壞

```
step 0        gradient_2norm 0.96      正常
step 2,269    val_loss 最佳 0.30065
step 3,508    gradient_2norm 0.135     全程最小(最健康)
step ~5,400   首次 spike,梯度開始失控
step 105,000  gradient_2norm 7.4×10⁵   完全失控
```

若為輸入標準化問題,第一步就會爆 —— **時序再次排除該假說**。

#### (c) 逐層分布:爆炸集中在輸入端

| 層 | 梯度中位數 |
|---|---|
| `layer1.blocks.0.attention.qkv.weight` | **2.17e6** |
| `patch_embed.conv_upper.weight` | **2.16e6** |
| `layer1.blocks.1.attention.qkv.weight` | 5.16e5 |
| `patch_embed.conv_surface.weight` | 5.48e4 |
| `layer2.blocks.0.attention.qkv.weight` | 4.91e4 |
| ⋯ | |
| `layer3.blocks.*.attention.proj.bias` | **~1e-6** |

**跨層相差 12 個數量級。** 架構為
`patch_embed → layer1 → downsample → layer2 → layer3 → upsample → layer4(+skip from layer1) → patch_recover`;
layer1 經 **U-Net skip connection** 直達 layer4,繞過深層路徑。梯度在此捷徑上放大,
深層(layer3)幾乎無梯度 ⇒ **網路實質退化為僅用淺層捷徑學習**。

#### (d) 裁剪已飽和,失去保護作用

95.6% 的步驟被壓到 norm = 2.0 ⇒ 優化器實際在做**固定步長**更新,
實際步長 = `lr × clip_val`。梯度再大也不改變步長,但**更新方向已惡化**。

#### (e) 推定機制(❓ 仍需實驗確認)

```
LR 過大 → 壞更新 → 激活值放大 → 梯度放大 → 裁剪飽和
       → 步長固定但方向持續惡化 → 正回饋失控
```

**但仍未解:baseline 用同樣的峰值 LR(4e-4)為何不會如此?**
剩餘變因:**bf16 精度**、**R=41 網格**、**vt/vr 表示法**。

#### (f) 關於 vt/vr 的補充事實

- 資料集**已預先存好** `vt`/`vr`/`vt10`/`vr10`,**本專案未執行任何旋轉**,
  僅讀取後以 `latlon_to_polar` 從笛卡兒 81×81 內插至 (r,θ)。
  ⇒ **其定義與慣例未經本專案驗證**。
- 訓練端 `r = linspace(0, r_max, R)` **包含 r=0**。該處 vt/vr 方向未定義(奇點),
  180 個 θ 全部取到同一格點值,但物理上 vt 應隨 θ 正弦變化 ⇒ 目標自相矛盾。
  惟該環僅佔 1/41 格點,**是否足以造成 1e6 量級梯度,尚無證據**。

#### (d) 結論

1. **bf16 是必要條件**。A 與 C 只差精度,C 爆而 A 沒爆;A2 在原始排程下再次確認。
2. **高 LR 是觸發條件**。同為 bf16,B(5e-5)零裁剪,C(4e-4)56% 裁剪。
3. **R=41、vt/vr、batch 32 全部無罪**。診斷 A 具備這三項卻完全健康
   —— §1 標記的「一次改五項無法歸因」由此解除。
4. 修任一個都有效,但**機制不同**:fp32 是移除成因,降 LR 只是減緩累積。

#### (e) 為什麼是 bf16 —— 震央的線索

三者尾數位數:**fp32 24 bits > fp16 11 bits > bf16 8 bits**
(相對誤差約 1e-7 / 5e-4 / 4e-3)。

震央是 `downsample.norm.{weight,bias}`(step 3,682 首先超標),而它們的健康期梯度
只有 **0.00056–0.00069**,是全網路最小的幾層之一 —— LayerNorm 參數梯度是「大量
正負項相加抵消」得來的小數,**對相對誤差最敏感**。

反向傳播順序為
`patch_recover → layer4 → upsample → layer3 → layer2 → downsample → layer1 → patch_embed`。
若爆炸來自輸出端,`layer4`/`patch_recover` 應**最先**失控;實測它們**最晚**
(23,083 / 5,582)⇒ **爆炸在 DownSample 就地產生,不是從上游傳來**。

> ⚠️ 震央位置、數值、擴散順序為實測;「LayerNorm 對相對誤差敏感」為推論,未直接驗證。

> **重要更正**:改用 `bf16-mixed` 是本報告先前的建議,理由是「避免溢位」。
> 但原版 LLAT 用 **fp16** 訓練成功,證明**範圍從來不是瓶頸,精度才是** ——
> 而 bf16 恰恰是三者中精度最差的。**這是一個判斷錯誤,已由本節實驗證實並修正。**

## 5. 結論

**達成**
1. 驗證了對 baseline 的診斷:`max_steps` 設定錯誤導致 LR 從未退火(6% vs 100%)
2. 取得 ~80× 吞吐提升,且各項貢獻可分解驗證
3. 修復 B7(bit-identical 驗證)、val batch_size;發現 B8(`GetPad2D` 的 5D 限制)
4. 確認 8 卡 DDP 正常運作(454 steps/epoch)

5. **成因已歸因**(§3.6):四組短診斷把「一次改五項」拆成單變數對照,
   確認是 **bf16 精度**,並洗清 R=41、vt/vr、batch 32
6. 建立可重現的實驗基礎設施(`OVERLAY` / `RUNDIR` / `FRESH`),使診斷可並行、可歸因

**未達成**
1. 新配置下訓練不穩定,最佳點出現在 epoch 5,後續 98% 的算力為負貢獻
2. 原始實驗一次變更五項 —— 雖已由後續診斷補救,但**這是本次最主要的方法論缺陷**

**下一步(依優先序)**

1. **正式訓練:`experiments/prod_fp32.yaml`**(fp32 + LR 4e-4,`max_steps: 96000`)

   | 設定 | 狀態 | 速度 | 短跑最佳 val |
   |---|---|---|---|
   | **fp32 + 4e-4** | ✅ 兩條長跑證據(baseline 199.6 h + A2) | 10,574 步/h | 0.28932 |
   | bf16 + 5e-5 | ✅ 短跑零裁剪,但長跑未驗證 | 15,283 步/h | **0.28707** |
   | fp16 + 4e-4 | ⚠️ 未測,**原版 LLAT 即用此設定** | ~15,000 步/h | — |

   選 fp32 的理由:失效機制是**捨入誤差隨參數更新累積**,降 LR 只減緩累積速度,
   而正式訓練的步數是診斷的 ~8 倍 ⇒ B 的「零裁剪」可能只代表「尚未累積夠」。
   fp32 是移除機制本身。代價僅 1.5× 牆鐘,而一次爆炸會浪費整整 9 小時。

   ⚠️ **換精度必須重算 `max_steps`**:fp32 實測 10,574 步/h
   (8 h → 85,600 | **9 h → 96,000** | 10 h → 107,000 | 12 h → 128,400)。
   沿用 bf16 的 105,000 會讓退火跑不完,重蹈 baseline 的覆轍。

2. **`16-mixed`(fp16)短診斷**(53 分鐘):尾數 11 bits > bf16 的 8 bits、
   速度與 bf16 相同、且原版 LLAT 已驗證。成功即可拿回 1.5× 的成本。
3. 推論端 Blocker(§7.1),使極座標版能產出預報圖
4. `r_min = Δr/2` 消除中心奇點(訓練端與推論端必須同時改)
5. 徑向 patch 過粗:`patch_r=8` 在 Δr=0.25° 下 = **2°/patch**,而 RMW 約 0.3–0.5°
   ⇒ 整個內核落在一個 patch 內,與「增加內核關注度」的目標衝突
6. 空間權重 `w(r) = r^p`(對治外圈欠約束;注意 p 不宜取 1,否則抵銷內核關注)
7. 加大 batch(GPU util 僅 25%,記憶體僅用 4%)

### 第一幕:任務與起點(S1–S3)

**S1 — 題目與動機**
- 一句話:老師的目標有兩個 —— **降低運算量**、**增加對內核的關注度**。
- 極座標為何同時滿足:token 數 3,528 → 1,920(**−46%**);而 (r,θ) 網格天生內密外疏,
  內核解析度自動變高。
- **這張不要講技術**,講「為什麼值得做」。

**S2 — 起點:學姊已經做到哪裡**
- 已有 `DLAMPty_polar` 原型:資料端 `latlon_to_polar` 動態轉換、模型端可跑、推論可畫圖。
- 但兩個現象:**訓練跑不完就被砍**、**預報圖「值都怪怪的」**。
- 誠實定位:**我不是從零開始,我是接手一個能跑但沒收斂的原型。**

**S3 — 我的三個目標**
1. 讓它在 NCHC H200 上**跑得完**
2. 找出「值都怪怪的」的**成因**
3. 建立**可重現、可對照**的實驗流程(而不是一次改五件事)

---

### 第二幕:診斷與工程(S4–S8)

**S4 — 先做的事:把架構的疑慮測掉**(時間不夠可刪)
- 曾懷疑三件事:θ 週期性、接縫、旋轉等變性。
- **實測結論:對這個 transformer 全都不是問題。** 因為它用**非重疊 patch embed**
  (stride = patch)+ 視窗注意力,θ 只要整除就完全不填充、也沒有跨邊界的重疊卷積
  ⇒ **沒有接縫成因**。循環填充 vs 零填充、拆 mask vs 留 mask,接縫比值全都 ~1.0。
- 這是**姊妹作 DSAT-2D(CNN)才有的問題**,不能直接套過來。
- 一句話:**「花時間證明某件事不是問題,和解決問題一樣有價值。」**

**S5 — 核心診斷:baseline 從未退火**
- 這是全場最強的一張。
- `max_steps` 設 1,600,000,實際只跑到 252,000(**15.8%**)
  ⇒ cosine 只走了開頭 ⇒ 訓練結束時 **LR 仍在峰值的 94%**。
- **模型從來沒有進入精修階段就被時間砍斷。**
- 配圖:兩條 LR 曲線疊圖(baseline 幾乎水平 vs 本次完整下降到 4e-11)。

**S6 — 工程:80× 吞吐**
- 每 epoch **2.85 小時 → 2.1 分鐘**;牆鐘 199.6 h → **6.7 h**。
- **關鍵是可分解驗證,不是喊數字**:
  `8 GPU (8×) × bf16 (2×) × 網格 R=41 (4.3×) × 移除死路徑 (1.18×) ≈ 81×`,實測 80×。
- DDP 正確性佐證:steps/epoch = 454 = 14,528/(4×8);baseline 是 3,706 ⇒ **等效只用了 1 張卡**。

**S7 — 順手修掉的問題**
- 挑三個講就好,重點在「**怎麼驗證修對了**」:
  1. `earth_specific_bias` 死路徑:全零、非 Parameter、每步 CPU→GPU 搬 26 MB
     → 移除後**輸出逐元素相同(max diff 0.000e+00)**、forward 快 18%。
  2. 驗證用 `batch_size` 寫死 1 → 改 4,驗證時間佔比 20% → 3%。
  3. θ 跨縫 attention mask:週期軸上禁止跨縫在語意上是錯的 → 拆除。
- 一句話:**「bit-identical 是重構的驗收標準。」**

**S8 — 假說驗證成功**
- LR 退火完成度 **6% → 100%**,排程完整執行。
- **對 baseline 的診斷得到證實。**

### 第三幕:誠實的新問題(S9–S12)

**S9 — 但是:模型在第 5 個 epoch 就達到最佳**(誠實的轉折)
- 最佳 val_loss 0.30065 @ epoch 5;最終 0.33168 @ epoch 231。
- **後續 226 個 epoch、98% 的算力是負貢獻。**
- 先排除最直覺的解釋:**不是過擬合**——train 與 val 同步震盪,且最終 val (0.3317)
  **低於** train (0.3364);過擬合的特徵是 train 續降、val 上升,與觀察相反。

**S10 — 找到決定性證據:梯度爆炸**
- 一張表講完:

  | | 梯度範數中位數 | 超過 clip=2.0 |
  |---|---|---|
  | baseline | **0.28** | 0.8% |
  | 本次 | **3.8 × 10⁶** | **95.6%** |

- **相差 1,300 萬倍。** 95.6% 的步驟被裁剪 ⇒ 優化器實際在做**固定步長**更新,
  **有效學習率由裁剪決定,而非由排程決定**。
- 逐層分布:爆炸集中在**輸入端**(`patch_embed` 2.16e6、`layer1.qkv` 2.17e6),
  深層 `layer3` 僅 ~1e-6,**跨層相差 12 個數量級**
  ⇒ 網路實質退化為只用 U-Net skip 的淺層捷徑學習。

**S11 — 排除法:四個假說死了三個**
- 這張展示的是**方法**,不是結論:

  | 假說 | 如何否證 |
  |---|---|
  | 過擬合 | train/val 同步且 val 較低 |
  | 輸入標準化異常 | 與原統計檔逐變數比對,31 個共用變數 ratio 全 = 1.0 |
  | 某個變數的資料壞掉 | 98 個變數的損失尖峰**在時間上同步**、天花板一致 ⇒ 全域事件 |
  | warmup 不足 | warmup 於 step 1,000 結束,首次 spike 在 step ~5,400(時序不符) |

- 最新發現讓假設進一步收斂:**損失健康(0.41)時梯度照樣 4e6**
  ⇒ 不是「LR 踩到損失懸崖」,是**梯度尺度本身的問題** ⇒ 主嫌指向 **bf16 精度**。

**S12 — 找出震央:是 DownSample 的 LayerNorm**
- 191 層的梯度各取「健康期(step 1,000–3,500)中位數」當基準,找**首次超過 10 倍**的 step:

  ```
  downsample     3,682   ← 震央(健康期梯度僅 0.00056,全網路最小之一)
  layer1         4,088
  patch_embed    4,291
  layer2         4,784
  layer3        11,324
  layer4        23,083   ← 最晚,差了近 20,000 步
  ```

- **關鍵論證**:反向傳播的順序是
  `patch_recover → layer4 → … → layer2 → downsample → layer1 → patch_embed`。
  若爆炸從輸出端傳來,`layer4` 該**最先**失控 —— 實測它**最晚**
  ⇒ **爆炸是在 DownSample 就地產生的。**
- 為什麼是它:LayerNorm 參數的梯度是「大量正負項相加抵消」得來的小數,
  **對相對誤差最敏感**,而 bf16 的尾數只有 8 bits(相對誤差 ~0.4%)。

**S13 — 結案:四組單變數診斷(這張是全場的收束)**

| | fp32 | bf16 |
|---|---|---|
| **LR 4e-4** | A: 0.23 ✅ / **A2: 0.25 ✅** | C: 9.8 ❌ / 原始: 147 ❌ |
| **LR 5e-5** | (未測) | B: 0.28 ✅ |

- **A2 是決定性的一組**:LR 軌跡與原始**逐點相同**(step 10,574 時兩者都是 3.92e-4),
  唯一差異是精度 —— fp32 全程 0.18–0.40,bf16 爬到 **1.1 萬**。
- **三個嫌疑犯當場無罪**:診斷 A 具備 R=41、vt/vr、batch 32 全部三項卻完全健康。
- 總共 **4 小時、4 個 job**,把 S9 的「一次改五項無法歸因」徹底解開。

**S14 — 我自己犯的錯,以及為此建的工具**(這張會加分)
- 錯誤一:**一次改五項** ⇒ 成因無法歸因。
- 錯誤二:診斷 A/B 為了縮短時間改 `max_steps`,而 cosine 長度來自
  `min(每epoch步數 × max_epochs, max_steps)` ⇒ **同時改了 LR 軌跡,又一次無法歸因**。
  改用 `max_time` 才修好(A2)。
- 錯誤三:**當初把精度改成 bf16 是我的判斷錯誤**。理由是「避免溢位」,
  但原版 LLAT 用 fp16 訓練成功,證明範圍從來不是瓶頸 —— 而 bf16 是三者中精度最差的。
- 補救:`OVERLAY` / `RUNDIR` / `FRESH` 三個環境變數,讓實驗只記錄差異、各自獨立、可並行。
- 一句話:**「我犯了三個錯,每一個都是被自己的實驗抓出來的。」**

### 7.4 建議修復順序

```
I2 (改 yaml,5 分鐘)
  → I1 (改 export 形狀)
  → I4 (匯出 onnx)          ← 到這裡才有東西可跑
  → I3 (R/Θ/r_max 改為從 yaml 讀,不再硬編碼)
  → I5+I6 (改 fill_value=NaN + 遮罩,或把 r_max 放大到 √2×40 涵蓋角落)
  → I9 (u/v → vt/vr 轉換)
  → I7 (縮排修正,順手)
  → I8 (延後,與下次訓練同步改)
```

**I5 的兩個修法要先決定**:
- **(a) 保守**:`fill_value=np.nan` + 下游遮罩 ⇒ 角落誠實標記為「模型未涵蓋」,畫圖留白。
- **(b) 積極**:訓練時就把 `r_max` 放大到 `40√2 ≈ 56.6` 格 ⇒ 極座標盤涵蓋整個方形域,無角落缺口。
  代價是格點數增加,且外圈取樣密度更稀疏。
- **建議先做 (a)**,因為 (b) 要重新訓練,而 (a) 立刻能讓圖變乾淨、也誠實。
